# UI and UX pass over Upkeep and Home, and the visual pass over the app

Status: In progress (PR A, B, B2, C, D1, D2a, D2b and D3 built, E1 and E2 built, F planned) · Owner: Igor Bondarenko · Last updated: 2026-11-19 · Source: three critical `ui-reviewer` passes (UI reassessment, UX ease of use, visual design) run on the merged maintenance work, and the owner's answers of 2026-11-05.

## Decisions (owner, defaults accepted)

- Nav order becomes Home, Groceries, Schedule, Upkeep, Items, People, Assistant, and Upkeep gets a wrench or loop icon. (Later, Items and Groceries became one Stock tab: `design-stock-page.md`.)
- Renames: Home "Due soon" becomes "Upkeep", Home "Your day" becomes "Today", Upkeep "Needs doing" becomes "Due now", "Add an item" becomes "Add job", "Out of it" becomes "Ran out" (and moves under Edit).
- Identity: the "Now" line carries through Schedule, a one-line summary sits under the Home date, a big weekday with a muted date, larger tabular time numerals, a small amber accent on the wordmark. No display font and no illustration unless asked.
- Slashed zeros stay on times; checked at 2 metres.
- Not adopted, with reasons: swipe and long-press (not discoverable, no keyboard route, wet hands), bottom sheets, command bars, inline row editing, skeleton loaders, a phone "More" tab, gradients, illustrations, a second font.

## PRs

- **A. Bugs and accessibility (built).** Plain-words input errors from the api (`errorFormatter`), name capped at 80, far dates told in months or with their year, one source for month names, second done on the same day refused in words, rail tightened and scrollable, phone labels at 11px, focus returns to the opener after a dialog and moves to the next Done after a Done, Undo toast waits while held and stays 15 seconds, quiet Dismiss.
- **B. Design foundations (built).** One status style (18px semibold) on every screen, darker bolder `late` plus a left border on overdue rows, a `--control` border token (about 3.5:1), shared `PageHeader`, one shared Home row, a shared Done size so Edit lines up, the overdue bar drawn in the card padding so no text moves, fade `h-8`, list pages capped at 3xl (Items, Groceries, People, Upkeep; Schedule is exempt because it already uses two columns from `lg`), "Any time" spelling, shorter Upkeep blurb, no "Chat" heading, lighter dark-mode card.
- **B2. Motion and phone sheets (built).** Dialogs become bottom sheets on phones (centred on tablet and desktop) that slide or fade in, the toast slides in, the row that moved flashes once after Done (Upkeep and Home), buttons give a small press response, the nav eases its colour. All 150 to 220 ms (the flash 1.4 s), all off under reduced motion (the rule also names pseudo-elements, since `*` misses the dialog backdrop), with tests for both. Entry animations only: a dialog or toast that closes is removed at once, so dismissing stays instant. Added at the owner's request: the app had no animation and its dialogs did not feel native. Known: on a real phone the on-screen keyboard may still cover the lower part of a tall sheet (the viewport now asks browsers that support it to resize for the keyboard); a sticky Save row comes with PR D.
- **C. Moving "Ran out" into the Items edit dialog moves to PR D, with the other dialog work; the maintenance toast gets its next-due wording there too.

- **E. Snooze.** "Not today" by a day, a week or a month, in two PRs (owner, 2026-11-19).
  - **E1. Shared, migration and api (built).** `maintenance_items.snoozed_until` (a local day, null when not snoozed); `maintenance.snooze({id, until, today})` with `until` null to clear (that is Undo), after today and within a year. A due or overdue job counts as Later until that day (`maintenanceStatus` takes the snooze; `daysUntil` and the due date stay real), then returns to Due now. Marking done clears it; editing keeps it. `list` returns `snoozedUntil`. Nothing visible in the app yet.
  - **E2. UI (built).** A quiet "Not today" button on due and overdue rows only (not on "soon" ones, since a snooze changes nothing for them), on the Upkeep page and the Home card; it comes before Edit and Done in Tab order. It opens the usual sheet with Tomorrow, In a week and In a month (each with its day) and Cancel; a toast "Furnace filter snoozed to 26 Nov." with Undo (the same `snooze` call with null). The snoozed job sits in Later and its status line reads "Snoozed to 26 Nov" (the status line, not a chip, so it is one place and in words). One toast at a time: a snooze closes the Done toast and a Done closes the snooze toast. Design pass (`homer-ui`, `frontend-design`): small, so no mock; existing `Dialog`, quiet and secondary buttons, token colours, 44px targets, no new colour or motion. Tests in `snooze.upkeep.spec.ts` (its own Playwright project at the end of the chain, with a phone width test) and `maintenanceText.test.ts`. The maintenance note job (PR 6 of `design-maintenance.md`) must skip snoozed jobs.
- **Bug fixes after E (owner, 2026-11-19).** Done today: a job whose last done date is today has no Done button (the api refuses a second done on the same day anyway), on the Upkeep page and the Home card. Errors: a failed save, Done or Undo shows as a red `ErrorToast` at the top (about 8 seconds, with Dismiss) instead of a line in the page; errors inside a dialog, field validation and "could not load" lines stay inline, because a message that fades would leave a blank page or a lost form. Tests in `errors.upkeep.spec.ts` and `feedback.upkeep.spec.ts`.
- **Dialog fixes (owner, 2026-11-19, from a real phone).** (1) The page behind a dialog no longer scrolls: `Dialog` pins the body where it is while any dialog is open (overflow hidden alone is ignored by iOS Safari) and puts it back after, and the sheet itself does not chain its scroll. (2, 3) On a touch screen no field takes focus when a dialog opens, because the keyboard covered the sheet before the title was read; focus starts on the title (a screen reader reads it), and a tap on a field raises the keyboard as usual. A mouse and keyboard still land on the first field. Every dialog's Save row (Cancel, Save, and Remove where there is one) is now the same sticky `DialogActions`, so Save stays on screen with 360px of height (a phone with the keyboard up); before, only the Upkeep dialogs had it. Field size is unchanged (44px targets, 16px text so iOS does not zoom). Known: with only 360px of height a long validation message sits two lines tall in the bar and takes a third of the sheet (it still works, nothing overlaps); the routine row dialog keeps "Remove row" beside Move up and Move down, not in the bar. The page also keeps its scrollbar space (`scrollbar-gutter: stable`) so content does not shift sideways while pinned. Not checked: a real iPhone keyboard (only Chromium here). Tests in `dialog.phone.on.spec.ts`.
- **Dialog fixes, round 2 (owner, 2026-11-19, a 6:11 PM phone screenshot).** On the real phone the Date and Time fields of Add event ran past the right edge of the sheet, and the first field had the keyboard up on open. Date and time fields now drop the native look (`appearance: none`, flex-centred, inner padding zeroed) so the width and height we set apply, like every other field; and after the dialog opens on a touch screen, focus is moved to the title if the browser put it on a field. Neither problem reproduced in Playwright's WebKit with an iPhone profile (the fields already fit and the title already had focus), so these are hardening, not a confirmed fix: a real iPhone has the last word. A new `iphone-webkit` e2e project (`*.webkit.spec.ts`, needs `playwright install webkit`) keeps the date and time fields the same size as the others in Safari's engine. An empty time field shows a grey "12:30 PM" in WebKit; that is its placeholder, not a value.
