# Slice 1: Items and days remaining. Technical plan and system design

Status: draft · Owner: Igor Bondarenko · Date: 2026-11-02 · Source: PRD §4.1, §6, §8 (slice 1)

## 1. Scope

**In:** create, edit and archive items (history is kept); restock; "Out of it"; days remaining and running-low flag; Items screen with forms. Restocks are recorded from the start.

**Out:** grocery list (slice 2), people/tasks/events (3), dashboard (4), assistant (5), PWA and Compose changes (6), learned estimate (7). The `days_per_unit_learned` column exists but stays null.

**Done when** (PRD §4.1, criteria 1 to 3; criterion 4 belongs to slice 7):
- Milk at 1 litre with 2 days per litre shows "Runs out in 2 days".
- Restocking milk with 4 litres updates the quantity and the days remaining.
- Days remaining is never negative. An item with no usage shows "No estimate".

## 2. System overview

```
 Browser (React, TanStack Query, tRPC client)
        │  HTTP  /trpc          (dev: Vite proxy :3000 → :3001; prod: nginx → api)
        ▼
 apps/api  Hono + tRPC adapter ──► routers/inventory ──► Drizzle ──► SQLite file (DATABASE_PATH)
        ▲                                   │
        └──── @homer/shared: Zod schemas + pure domain functions (used by web, api, and later LLM tools)
```

- Same origin through the proxy, so no CORS.
- All domain math lives in `packages/shared/src/domain.ts`: pure, no I/O, and shared by server and UI.
- Computed values (days remaining, running low) are derived on read and never stored.

## 3. Data model

`items`

| column | type | notes |
|---|---|---|
| id | integer pk autoincrement | |
| name | text not null | unique, case-insensitive, among active (non-archived) items only |
| unit | text not null | e.g. "bag" |
| quantity | real not null, ≥ 0 | real, so half a litre is allowed |
| days_per_unit_entered | real null | null means no estimate |
| days_per_unit_learned | real null | unused in slice 1 |
| low_threshold_days | integer not null default 7 | |
| created_at | text (ISO-8601 UTC) | |
| archived_at | text (ISO-8601 UTC) null | set when the item is removed; null means active |

Items are never hard-deleted. "Delete" in the UI archives the item: it disappears from lists, but its row and restock history stay for later queries (for example asking the assistant for an item's history).

`restocks`

| column | type | notes |
|---|---|---|
| id | integer pk | |
| item_id | integer fk → items.id, no cascade | history outlives archiving; rows are append-only |
| quantity | real not null, > 0 | amount added |
| restocked_at | text (ISO-8601 UTC) | |

Setup: SQLite with WAL and `foreign_keys=ON`. Migrations are generated by drizzle-kit (`apps/api/drizzle.config.ts`, output in `apps/api/drizzle/`) and applied on API boot with the Drizzle migrator. `pnpm db:migrate` runs the same migrations by hand. The DB is never edited directly (guard hook).

## 4. Shared package (`packages/shared/src`)

No Node or DOM types.

- `schemas.ts`
  - `itemSchema` (the row)
  - `itemInputSchema`: name non-empty, unit non-empty, quantity ≥ 0, `daysPerUnit` > 0 or null, threshold ≥ 0
  - `restockInputSchema`: `{ itemId, quantity > 0 }`
- `domain.ts`
  - `effectiveEstimate(item)` returns `{ daysPerUnit, source: "entered" | "learned" } | null` (learned wins over entered)
  - `daysRemaining(quantity, daysPerUnit | null)` returns `number | null`. Null means "No estimate". The result is floored and never below 0.
  - `isRunningLow(days, thresholdDays)`: true when days is not null and ≤ threshold
- `index.ts` re-exports all of the above.

## 5. API (`apps/api/src`)

- `db/schema.ts`: Drizzle tables. `db/client.ts`: better-sqlite3 opened from `DATABASE_PATH`.
- `trpc.ts`: tRPC init. `routers/inventory.ts` has these procedures:
  - `list`: active items only (`archived_at` is null), each with `daysRemaining`, `runningLow`, `estimateSource`, and `usualRestock` (the last restock quantity, used to prefill "Bought it")
  - `create`, `update`, `archive` (sets `archived_at`; never removes rows)
  - `findArchived({ name })`: the most recently removed item with that name (case-insensitive), or null
  - `restore({ id, ...itemInput })`: brings a removed item back with its history and the submitted values; keeps the original name; fails with CONFLICT if an active item already has that name
  - `history({ id })`: restocks for an item, newest first, including archived items. No screen in slice 1; it is the read path the assistant tool will use later.
  - `restock({ itemId, quantity })`: in one transaction, adds to the quantity and inserts a `restocks` row
  - `markOut({ itemId })`: sets the quantity to 0
- `routers/index.ts` exports `AppRouter`. `index.ts` mounts Hono, with tRPC at `/trpc`, and listens on `PORT`.
- Every input is validated with the shared Zod schemas. Invalid input is rejected and nothing is written.

## 6. Web (`apps/web/src`)

- `vite.config.ts` (react plugin, tailwind plugin, `/trpc` proxy to :3001), `index.html`, `main.tsx`, `trpc.ts` (typed client plus QueryClient), react-router with the Items page only.
- **Items page:** single column on phones and a grid on larger screens. Cards are sorted by days remaining, lowest first, and items with no estimate go last. Each card shows:
  - name and quantity with unit
  - a plain-words line: "Runs out in 2 days" or "No estimate"
  - one primary action, "Bought it", which opens a restock dialog prefilled with the usual amount
  - a secondary "Out of it"
- **Add and edit form:** name, unit, quantity, "Lasts (days per unit)", "Low at (days)".
- **Re-adding a removed item:** on save, the page calls `findArchived`. If a removed item has that name, a dialog asks "Restore it" (same item, history kept, original name) or "Start a new item" (new id, empty history), with Cancel returning to the form with its values intact.
- **Cards:** a flex column with the button row pinned to the bottom, so buttons line up across a row even when one card has no estimate note.
- **Favicon:** `apps/web/public/favicon.svg`, linked from `index.html`, with a dark-mode variant.
- Rules: `homer-ui` (44px targets, dark mode, Tailwind only, keyboard reachable, urgency in words) and `coding-style` (arrow functions, immutable, labels read like identifiers, files under about 600 lines).

## 7. Testing (red-green-refactor)

- **Domain, with fast-check:**
  - `daysRemaining` is never negative.
  - It is null exactly when there is no estimate.
  - It is monotonic in quantity.
  - `isRunningLow` flips exactly at the threshold.
  - Example cases: milk 1 l × 2 d gives 2; salt with no estimate gives null.
- **Router tests**, using `createCaller` on an in-memory SQLite DB:
  - `restock` raises the quantity and writes a history row, atomically.
  - `markOut` zeroes the quantity.
  - Invalid inputs are rejected.
  - Archiving an item hides it from `list` but keeps its restocks, and `history` still returns them.
  - Creating an item with the name of an archived one is allowed.
  - `findArchived` matches case-insensitively and returns the most recently removed item.
  - `restore` brings back an item with its history, and rejects an item that isn't removed or whose name is now taken.
- **UI:** checked in the running app (VERIFY phase). Browser checks use the Playwright MCP (configured in `.mcp.json`).

## 9. Decisions and risks

- **Rounding:** days are floored, so 1 l × 2 days gives "2 days" and 0.5 l gives "1 day".
- **Usual restock amount** is the last restock quantity until slice 7.
- **Native build:** `better-sqlite3` on Node 24 and pnpm 12 is checked first in step 2, because a failed build would block everything after it.
- **Name uniqueness** is case-insensitive, so "Salt" and "salt" are one item. This also helps the assistant later.
- **Chat model:** `qwen3.5:9b` is the single chat and tool-calling model across `.env.example`, the PRD and CLAUDE.md. It doesn't affect slice 1.
- **Name matching is ASCII-only:** SQLite's `lower()` folds only ASCII, so "Étagère" and "étagère" count as different names.
- **Edit overwrites quantity:** the edit form sends the quantity it loaded, so a restock made on another tablet in the meantime can be overwritten. Accepted for one household in v1.
- **Bounds:** quantity is capped at 100,000 and days per unit at 3,650, so days remaining always stays a finite number.
- **Decided (owner, 2026-11-02):** history is never deleted. Removing an item archives it and its restocks stay, so history can be shown later or asked for in chat.
- **Decided (owner, 2026-11-02):** re-adding an item whose name was removed before asks in the UI whether to restore the old item (history kept) or start a new one.
